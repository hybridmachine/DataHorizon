## Implementation contract

Use the existing workbook `POST operations` entry point. Ordinary structural edits return their existing receipt. An oversized edit returns HTTP 409 with code `LARGE_STRUCTURE_CONFIRMATION_REQUIRED` and outcome `rejected`, before invoking a hook or reserving a durable operation ID. The caller can confirm by sending the same command, expected state and operation ID with `confirm_large_structure: true`. The response for a running job contains `operation_id` and `status: running`. Poll `GET operations/{id}/status` for `status` (running, completed or failed), `phase`, and terminal `receipt` or `error`. Use the existing operation cancellation and durable receipt endpoints. A lost response requires reconciliation using the original ID.

The engine will use disk-backed staging where overlapping coordinate shifts or streamed formula rewrites require it. Compare both paths at the threshold, including a small shift with enough unrelated formulas to exceed the scan budget. Exercise the six operations on equivalent fixtures with preserved identities, existing metadata rules and transactional hook edits. The large-workbook harness will reopen and inspect the persisted result independently and report resource usage. Update the compatibility and implementation records with the observed results.
