## Implementation contract

Use the existing workbook `POST operations` entry point. Ordinary structural edits return their existing receipt. An oversized edit returns HTTP 409 with code `LARGE_STRUCTURE_CONFIRMATION_REQUIRED` and outcome `rejected`, before invoking a hook or reserving a durable operation ID. The caller can confirm by sending the same command, expected state and operation ID with `confirm_large_structure: true`. The response for a running job contains `operation_id` and `status: running`. Poll `GET operations/{id}/status` for `status` (running, completed or failed), `phase`, and terminal `receipt` or `error`. Use the existing operation cancellation and durable receipt endpoints. A lost response requires reconciliation using the original ID.

The engine will use disk-backed staging where overlapping coordinate shifts or streamed formula rewrites require it. Compare both paths at the threshold, including a small shift with enough unrelated formulas to exceed the scan budget. Exercise the six operations on equivalent fixtures with preserved identities, existing metadata rules and transactional hook edits. The large-workbook harness will reopen and inspect the persisted result independently and report resource usage. Update the compatibility and implementation records with the observed results.

## Implementation and verification

The engine stages the original and destination coordinates in temporary SQLite tables. It streams formula rewrites and validates the stored inputs before applying the coordinate change. The worker has a 300-second execution budget. Ordinary edit, hook and metadata limits still apply to their respective operations. A review that exhausts its five-second budget also offers background execution. Confirming on the first submission is supported when the caller already has the operation ID and reviewed state. [Engine implementation](../../service/datahorizon/large_structure.py) · [Managed client guide](development.md)

The ordinary and staged paths were compared on all six operations. The regression fixtures include declared records, presentation metadata, charts, names, cell bindings, malformed external data, grid overflow and structural hook rollback. Service tests cover confirmation, stale review, concurrent status and cancellation, shutdown, a lost acknowledgement and the original receipt after a retry. Desktop tests exercise the real row-insertion command and both confirmation choices. [Engine tests](../../tests/test_large_structure_engine.py) · [REST and client tests](../../tests/test_large_structure_service.py) · [Desktop tests](../../tests/test_desktop.cpp)

The capacity fixture contains 50,000 rows by 20 columns on the edited sheet, 1,000 cross-sheet formulas across two sheets, and a chart on each sheet. Each run starts from the same native file and uses a fresh service. A second service reopens the file and checks the receipt. An independent SQLite reader compares every stored cell, formula and style with the expected coordinate mapping and checks chart anchors, sources and sheet identity. The interrupted runs wait for a live rollback journal before requesting cancellation or killing the worker process. The crash case can recover the original workbook with no durable receipt. A client in that situation continues to report an unknown outcome. [Qualification driver](../../tests/qualify_large_structure.py) · [Capacity measurements](evidence/large-structural-edits-capacity.json)

On Apple Silicon with macOS 26.6.2, Python 3.14.6 and SQLite 3.53.4, the six confirmed edits on revision `bbc0adf` took **5.93–12.34 seconds** each. Sampled peak service RSS was **41.8–45.3 MiB**. The workbook and its named journal grew by up to 68.9 MiB during a run. The largest sampled decrease in free space on the volume was 300.1 MiB, which can include unlinked SQLite staging files and other concurrent activity. These measurements describe this fixture and host. The returned receipts survived a service restart. Discarding the row insertion acknowledgement and resubmitting the same command produced the original receipt and one shift. Cancellation restored the before state with a rolled-back receipt. A forced service exit restored the before state with an unknown receipt outcome.

The complete CMake build succeeded. All six CTest targets passed in 769.67 seconds, including 289 desktop, 72 Python workspace and 227 chart-authoring Qt checks. The service suite ran 1,736 tests with 28 dependency-specific skips in its default interpreter. Those 28 cases passed separately in the existing OpenAPI validation, spreadsheet interchange and APSW environments. The Qt tests ran offscreen on macOS. Windows, Linux and physical-input acceptance remain open.
