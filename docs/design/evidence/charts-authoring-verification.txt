6. Export check of a chart made through the authoring operations
-----------------------------------------------------------------
Scope: an agent cannot use a physical mouse and keyboard. A throwaway script outside the repository (not committed)
used the Python SDK (datahorizon.client.LocalService) to send exactly what the desktop sends, in the desktop's order:
  - fill Sheet1!A1:C13 (Month, Sales, Cost; twelve rows);
  - Insert -> Chart over A1:C13: suggest_chart(r1=1, c1=1, r2=13, c2=3), then chart_create with the suggested spec and
    anchor row 1, column 4 (the selection's top row, one column right of it); name and size left to the engine
    (it stored "Chart 1", column, clustered, anchor D1, offset 0,0, 480x300);
  - the panel's type button Bar: chart_update with a whole spec in input form (sources by sheet id), type bar,
    grouping kept clustered;
  - the panel's Title on Enter: chart_update with a whole spec built from the relisted chart, title
    {"text": "Sales and cost by month"};
  - a drag: chart_update with anchor {row 3, col 6} and offset {12, 7};
  - a top-left handle resize: chart_update with anchor, offset and size {520, 340}.
All five operations committed. The script's first run stopped at the title step with "title must be an object": the
script had sent the title as a string, which the panel never does (it sends {"text": ...}); the script was corrected
and run again on a fresh workbook. That is a script error, not a product finding.
The workbook was then exported with export_spreadsheet(fmt, scope="workbook") (the inline whole-workbook route) and
each file read back with the import preview (xlsx_preview / ods_preview, scope "workbook"):
  xlsx: 4,161 bytes; report "Charts: 1 written."; 1 chart read back; equal: yes; no chart or drawing import entry
  ods:  2,367 bytes; report "Charts: 1 written."; 1 chart read back; equal: yes; no chart or drawing import entry
Compared: name ("Chart 1"), type (bar), grouping (clustered), title, legend (right), categories (Sheet1 A2:A13),
series names (B1, C1) and values (B2:B13, C2:C13), anchor (F3), offset (12, 7), size (520x340).
Files (not tracked by git):
  /Users/btabone/source/DataHorizon/output/charts-authoring-samples/authored-chart.xlsx
  /Users/btabone/source/DataHorizon/output/charts-authoring-samples/authored-chart.ods
This exercised the same operations the desktop sends, through the service, but not the desktop UI itself. The
desktop UI path (Insert -> Chart, the drags, the keys and the panel sending these operations) is covered by the
automated chart_authoring tests of item 2, which drive mouse and key events through Qt on the offscreen platform.
